# sensors-ui — клієнтський застосунок (Next.js)

Інтерфейс моніторингу давачів температури та диму. Проєкт з лаб. №2; у лаб. №3
сторінки з графіками беруть дані із серверного застосунку `sensors-api`
замість випадкових чисел.

## Запуск локально

```
npm install
npm run dev
```

Відкрийте http://localhost:3001. Порт 3001 обрано, щоб не конфліктувати із
сервером NestJS на 3000.

Адреса сервера задається у файлі `.env`:

```
NEXT_PUBLIC_API_URL=http://localhost:3000
```

Для сервера на Render підставте `https://<назва>.onrender.com`. Після зміни
`.env` перезапустіть `npm run dev`.

## Розгортання на Vercel

Імпортуйте репозиторій, Framework Preset — Next.js. У **Environment Variables**
додайте `NEXT_PUBLIC_API_URL` з адресою сервера на Render. Файл `.env` у
репозиторій не потрапляє (він у `.gitignore`), тому без цієї змінної сайт не
знатиме адреси сервера. Після зміни змінної потрібен Redeploy.

## Сторінки

| Адреса | Файл | Що там |
|---|---|---|
| `/` | `app/page.tsx` | опис і адреса сервера, з яким працює клієнт |
| `/dashboard-temp` | `app/dashboard-temp/page.tsx` | графік температури з `GET /temperature-sensors` |
| `/dashboard-smoke` | `app/dashboard-smoke/page.tsx` | графік диму з `GET /smoke-sensors`, поріг і тривога із сервера |
| `/login` | `app/login/page.tsx` | форма входу, поля й кнопка заблоковані |

## Структура

```
app/                    сторінки (App Router: папка = адреса)
components/
  Navbar.tsx            навігація
  SensorChart.tsx       графік recharts, спільний для обох давачів
  StatCard.tsx          картка з одним показником
  DataState.tsx         повідомлення замість графіка: завантаження / помилка / порожньо
lib/
  api.ts                адреса сервера з NEXT_PUBLIC_API_URL і типи записів
  useSensorData.ts      хук: GET кожні 5 с і POST нового показання
  chart.ts              розрахунок поділок осі Y
.env                    адреса сервера для локального запуску (не потрапляє в Git)
.env.example            зразок .env (потрапляє в Git)
```

## Як сторінка отримує дані

1. `useSensorData("/smoke-sensors", 5000)` робить `fetch(API_URL + path)` одразу
   після відкриття сторінки і далі кожні 5 секунд.
2. Сервер повертає масив записів; сторінка бере останні 20 і перетворює кожен на
   точку графіка: `time` — з `timestamp`, `value` — з `value`.
3. Для диму поля `alarm` і `threshold` приходять із сервера готовими — клієнт
   тривогу не рахує, а лише показує.
4. Кнопка «Додати показання» надсилає POST на той самий маршрут і перечитує масив.
